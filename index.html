// Git 101 · 02

Git ≠ GitHub

Git

本機的存檔工具

  • 裝在你的電腦上的程式
  • 記錄每一次修改，隨時回到過去
  • 沒有網路也能用
$ git commit
≠

GitHub

放 Repo 的雲端網站

  • 把專案放上網路，換電腦也拿得到
  • 跟組員一起改同一份程式
  • 同類服務還有 GitLab、Bitbucket
github.com/你的帳號

就像打遊戲：Git 是存檔功能，GitHub 是雲端存檔，換台主機也能接著玩

// Git 101 · 03

4 個核心名詞

Repository 儲存庫

一個被 Git 管理的專案資料夾

一個存檔欄位

Commit 提交

幫目前的檔案拍一張快照，附上一句說明

存檔點，隨時可以讀檔回去

Branch 分支

開一條平行世界試新功能，成功再 merge 回 main

開支線劇情，不怕玩壞主線

Push / Pull 推送 / 拉取

push 把本機 commit 傳上 GitHub；pull 把別人的更新抓下來

上傳 / 下載雲端存檔

// Hands-on · GitHub Pages

用 Gemini 寫網頁，用 GitHub Pages 架上網

STEP 01/ 12

登入 GitHub

打開 github.com 登入，進到 Dashboard。

STEP 02/ 12

進入 Repositories

點右上角的頭像 → Repositories。

STEP 03/ 12

建立新的 Repo

點右上角綠色的 New 按鈕。

STEP 04/ 12

命名並設為 Public

Repository name 填 my_website，Visibility 選 Public，按 Create repository。

免費版 GitHub Pages 只能用 Public 的 Repo

STEP 05/ 12

新增一個檔案

在 Quick setup 區塊點 creating a new file。

STEP 06/ 12

請 Gemini 幫你寫網頁

打開 Gemini，直接用中文跟它說你要什麼，再把它產生的 HTML 程式碼複製起來。

幫我用 html 格式介紹特斯拉最新款差別

STEP 07/ 12

貼上程式碼

檔名打 index.html，把 Gemini 給的程式碼整段貼進編輯區。

首頁檔名一定要叫 index.html

STEP 08/ 12

Commit 存檔

按右上角 Commit changes…，訊息填 Create index.html，再按 Commit changes。

Commit ＝ 幫這次修改存一個版本

STEP 09/ 12

開啟 GitHub Pages

Settings → 左側 Pages，Branch 選 main、資料夾 / (root)，按 Save。

STEP 10/ 12

等它部署

出現 being built from the main branch 代表正在部署，等 1～2 分鐘後重新整理。

STEP 11/ 12

拿到你的網址

出現 Your site is live at，網址格式是 https://帳號.github.io/repo名稱/。

STEP 12/ 12

上線！

打開網址，你的網頁已經在網路上，傳給任何人都看得到。

// Security 101 · 01

資安在保護什麼？

用學校的「成績系統」來想

C

機密性 Confidentiality

你的成績只有你和老師看得到

被破壞：同學偷看到全班成績

I

完整性 Integrity

成績不會被偷偷改掉

被破壞：有人把 59 分改成 60 分

A

可用性 Availability

要查成績的時候系統打得開

被破壞：選課當天網站被灌爆掛掉

// Security 101 · 03

Web 網站安全請求、登入與資料權限

網址拿到了，也不能看私人影片

別人→ watch?v=私人影片→ 這是私人影片

YouTube 影片可以設成公開、不公開、私人。

就算知道網址，伺服器每一次都要檢查「你有沒有權限看」。

不應該完全信任任何人

真實案例 · 2020

YouTube：私人影片被「另一個入口」看光

  1. YouTube 網站本身會擋私人影片，但 Google Ads 有個功能可以抓任一影片的畫面
  2. 這個入口只看影片 ID、沒檢查權限，研究員 David Schütz 用它把私人影片一格一格抓出來
  3. 回報給 Google 後修好，拿到 5,000 美元漏洞獎金

每一個能拿到資料的入口，都要檢查權限

// Security 101 · 04

Network 網路安全封包、連線與信任

封包到了，對方真的是誰？

DNS 像電話簿：網址 → IP。被竄改就會被帶去假網站。

TLS：網址列的 ，憑證有效、內容有加密。

看到憑證警告，不要硬按「繼續前往」

真實案例 · 2018

MyEtherWallet：網址打對了，連到的卻是假網站

  1. 駭客劫持了 DNS 路由，把 myetherwallet.com 導到自己架的假網站
  2. 假網站沒有正確的憑證，瀏覽器跳出警告
  3. 不少人按「繼續前往」並輸入錢包私鑰，約 15 萬美元的以太幣被偷走

憑證警告就是在說「對方可能不是本人」

// Security 101 · 07

Crypto 密碼學加密、雜湊與驗證的保證

加密 Encryption有金鑰就能解密回來 → 防偷看

hello+→x9#Lq@2z

例子｜傳 LINE 訊息你打「明天考試範圍？」，傳出去是一串亂碼，只有同學的手機能用金鑰解開。中間被攔截，也看不懂。

雜湊 Hashing固定長度、無法還原 → 拿來比對

hello→2cf24dba5fb0…

例子｜網站存密碼註冊時，資料庫只存密碼 1234 的雜湊 03ac6742…。登入時把你輸入的再雜湊一次，一樣就放行。資料庫外洩，駭客也拿不到原本的密碼。

真實案例 · 2012

LinkedIn：密碼有雜湊，還是被破解

  1. 650 萬組密碼雜湊被駭客公開在網路上
  2. 用的是又快、又沒「加鹽」的 SHA-1：一樣的密碼，雜湊也一模一樣
  3. 駭客拿常見密碼表一個個算來比對，很快就破解大半，最多人用的是 123456

存密碼要用 bcrypt 這類慢雜湊 + 加鹽；自己也別用 123456
