// Git 101 · 02

Git ≠ GitHub

💾

Git

本機的存檔工具

  • 裝在你的電腦上的程式
  • 記錄每一次修改，隨時回到過去
  • 沒有網路也能用
$ git commit
≠
☁️

GitHub

放 Repo 的雲端網站

  • 把專案放上網路，換電腦也拿得到
  • 跟組員一起改同一份程式
  • 同類服務還有 GitLab、Bitbucket
github.com/你的帳號

🎮 就像打遊戲：Git 是存檔功能，GitHub 是雲端存檔，換台主機也能接著玩

// Git 101 · 03

4 個核心名詞

Repository 儲存庫

一個被 Git 管理的專案資料夾

🎮 一個存檔欄位

Commit 提交

幫目前的檔案拍一張快照，附上一句說明

🎮 存檔點，隨時可以讀檔回去

Branch 分支

開一條平行世界試新功能，成功再 merge 回 main

🎮 開支線劇情，不怕玩壞主線

Push / Pull 推送 / 拉取

push 把本機 commit 傳上 GitHub；pull 把別人的更新抓下來

🎮 上傳 / 下載雲端存檔

// Security 101 · 03

🌐 Web 網站安全請求、登入與資料權限

網址拿到了，也不能看私人影片

🙋 別人→ watch?v=私人影片→ 🛑 這是私人影片

YouTube 影片可以設成公開、不公開、私人。

就算知道網址，伺服器每一次都要檢查「你有沒有權限看」。

不應該完全信任任何人

真實案例 · 2020

YouTube：私人影片被「另一個入口」看光

  1. YouTube 網站本身會擋私人影片，但 Google Ads 有個功能可以抓任一影片的畫面
  2. 這個入口只看影片 ID、沒檢查權限，研究員 David Schütz 用它把私人影片一格一格抓出來
  3. 回報給 Google 後修好，拿到 5,000 美元漏洞獎金

💡 每一個能拿到資料的入口，都要檢查權限

// Security 101 · 04

📡 Network 網路安全封包、連線與信任

封包到了，對方真的是誰？

DNS 像電話簿：網址 → IP。被竄改就會被帶去假網站。

TLS：網址列的 🔒，憑證有效、內容有加密。

看到憑證警告，不要硬按「繼續前往」

真實案例 · 2018

MyEtherWallet：網址打對了，連到的卻是假網站

  1. 駭客劫持了 DNS 路由，把 myetherwallet.com 導到自己架的假網站
  2. 假網站沒有正確的憑證，瀏覽器跳出警告
  3. 不少人按「繼續前往」並輸入錢包私鑰，約 15 萬美元的以太幣被偷走

💡 憑證警告就是在說「對方可能不是本人」

// Security 101 · 05

🔍 Reverse 逆向工程從程式推回它的行為

只有執行檔，也要看懂它

📦 crackme→ ❓ 輸入什麼？→ OK! 
// 反組譯後大概長這樣
if (check(input) == 1)
    puts("OK");
else
    puts("Wrong");

沒有原始碼，就反組譯、觀察分支與流程。

真實案例 · 2017

WannaCry：逆向分析找到病毒的「關機開關」

  1. 勒索病毒在 150 個國家擴散，20 多萬台電腦被加密，英國醫院也停擺
  2. 研究員 Marcus Hutchins 逆向分析病毒，發現它會先去連一個沒人註冊的網域
  3. 他花約 10 美元註冊那個網域，病毒就停止擴散了

💡 看懂程式在做什麼，就找得到它的弱點

// Security 101 · 06

💥 Pwn 二進位漏洞利用輸入如何跨越記憶體邊界

看懂程式，再看邊界

ABCD E隔壁的資料

← 預留 4 格 →

預留 4 格，卻寫進第 5 格？

缺少邊界檢查，可能破壞相鄰資料 💥

真實案例 · 2014

Heartbleed：少檢查一個長度，記憶體被讀光

  1. HTTPS 常用的 OpenSSL 有個「心跳」功能：你傳一個字，伺服器回你同一個字
  2. 攻擊者說「我傳了 64KB」，其實只傳了 1 個字
  3. 伺服器沒檢查長度，把記憶體裡隔壁的資料一起回傳：密碼、私鑰都可能在裡面

💡 別相信使用者給的長度，永遠自己檢查

// Security 101 · 07

🔐 Crypto 密碼學加密、雜湊與驗證的保證

加密 Encryption有金鑰就能解密回來 → 防偷看

hello+🔑→x9#Lq@2z

例子｜傳 LINE 訊息你打「明天考試範圍？」，傳出去是一串亂碼，只有同學的手機能用金鑰解開。中間被攔截，也看不懂。

雜湊 Hashing固定長度、無法還原 → 拿來比對

hello→2cf24dba5fb0…

例子｜網站存密碼註冊時，資料庫只存密碼 1234 的雜湊 03ac6742…。登入時把你輸入的再雜湊一次，一樣就放行。資料庫外洩，駭客也拿不到原本的密碼。

真實案例 · 2012

LinkedIn：密碼有雜湊，還是被破解

  1. 650 萬組密碼雜湊被駭客公開在網路上
  2. 用的是又快、又沒「加鹽」的 SHA-1：一樣的密碼，雜湊也一模一樣
  3. 駭客拿常見密碼表一個個算來比對，很快就破解大半，最多人用的是 123456

💡 存密碼要用 bcrypt 這類慢雜湊 + 加鹽；自己也別用 123456

// Security 101 · 08

🕵️ DFIR 數位鑑識從證據重建發生過什麼

資料外洩後，先找證據

  1. 18:01🔑 陌生登入
  2. 18:03📄 大量讀取紀錄
  3. 18:05📤 對外傳送資料

日誌 Log、網路封包、檔案與記憶體，拼起事件經過。

真實案例 · 2016

第一銀行 ATM 盜領案：ATM 自己吐錢

  1. 全台 41 台 ATM 在沒人操作下自動吐鈔，被領走約 8,300 萬元
  2. 鑑識人員從主機和 ATM 的日誌、留下的惡意程式，追出駭客是從倫敦分行的系統入侵
  3. 再配合監視器抓到車手，大部分的錢都追回來

💡 寫程式記得留 log，出事時才查得到
